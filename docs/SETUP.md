# Установка и эксплуатация Hotel Insight AI

Система подбирает отели по свободному запросу: вид на море и закат, тишина,
дорога пешком до пляжа, ночные заведения, инфраструктура для детей и правила для питомцев.

**Gemini — основной способ понимания запроса.** Модель выделяет критерии, код ищет и
ранжирует реальные записи SQLite, затем Gemini объясняет результат. При сбое API
пользователь видит причину и резервный результат, а не пустой экран.

Все команды ниже выполняются **из корня репозитория**. Рекомендуется Python 3.11+;
текущая версия проверялась на macOS с Python 3.14. Установка зависимостей требует интернета.

## 1. Установка и настройка

macOS / Linux, первый запуск:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
# Существующий .env с ключом не перезаписывается:
test -f .env || cp .env.example .env
```

Откройте `.env` в редакторе и заполните `GEMINI_API_KEY`. `GEMINI_MODEL` должен
соответствовать модели, доступной вашему ключу. Ключ не нужно вставлять в код или README.
`.env` и `.venv` исключены из Git. Пустой ключ включает явно обозначенный резервный
режим. Основной сценарий проекта — поиск через Gemini.

В уже установленном проекте достаточно активировать окружение и обновить зависимости:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Windows PowerShell, первый запуск:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

В командах далее используется `python` из активированного окружения.
Если активация PowerShell запрещена локальными настройками, вместо `python` можно
вызывать `.\.venv\Scripts\python.exe`, а сайт запускать через `-m streamlit`.

## 2. База данных и запуск сайта

Приложение читает **`data/demo/facts.db`**, а не `hotels.json` напрямую.
SQLite-БД локальная и **не входит в Git**. В репозитории поставляются `hotels.json`
и `scene.npz` для **синтетического городка из восьми отелей**.
У вас уже может быть другая локальная БД, например с настоящими отелями Адлера.

При первом запуске, **только если БД отсутствует**, импортируйте поставляемый JSON.
macOS / Linux — этот блок сохраняет существующую БД:

```bash
if [ ! -f data/demo/facts.db ]; then
  python scripts/import_hotels.py data/demo/hotels.json --city Сочи &&
  python scripts/seed_hotelier_demo.py
fi
python -m streamlit run app/streamlit_app.py
```

Windows PowerShell:

```powershell
if (-not (Test-Path data/demo/facts.db)) {
  python scripts/import_hotels.py data/demo/hotels.json --city Сочи
  if ($LASTEXITCODE -ne 0) { throw 'Импорт не выполнен' }
  python scripts/seed_hotelier_demo.py
}
python -m streamlit run app/streamlit_app.py
```

Блоки проверяют стандартный путь БД. Если вы специально задавали переменную
окружения `HOTELS_DB`, используйте её путь вместо `data/demo/facts.db`.
`seed_hotelier_demo.py` предназначен только для синтетических ID `w1..w8`, не для реальных отелей.

Сайт запускается на компьютере; адрес и порт напечатает Streamlit (обычно
`http://localhost:8501`). Терминал остаётся занят сервером, остановка — `Ctrl+C`.
Для доступа только с этого компьютера добавьте `--server.address 127.0.0.1`.

Консольный поиск — отдельная команда вместо сайта или из второго терминала:

```bash
python main.py "Хочу море в пешей доступности в Сочи"
```

**Не запускайте импорт повторно без необходимости:** по умолчанию
`import_hotels.py` очищает выбранную БД перед импортом. `--keep` сохраняет
существующие записи, но может добавлять повторные факты — это не полная замена набора данных.

## 3. Проверка Gemini онлайн

После заполнения `.env`:

```bash
python scripts/check_gemini_search.py --query "Хочу море в пешей доступности"
# Все три сценария, включая новую формулировку и неизвестное пожелание:
python scripts/check_gemini_search.py
```

`ONLINE PASS` означает, что Gemini разобрал запрос, отели найдены и не было
резервного объяснения. Fallback не засчитывается как онлайн-успех; скрипт возвращает
код 1. На сайте после «Найти» указан **фактический** режим разбора и причины сбоев.
Наличие ключа само по себе не доказывает успешное обращение к API.

429 — ограничение частоты или квоты ключа; 503 — временная недоступность сервиса.
Не повторяйте запросы непрерывно. Проверяйте квоту, доступ к модели и значение
`GEMINI_MODEL`. Таймаут — 20 секунд на попытку, максимум один повтор;
планирование и объяснение являются отдельными вызовами.

Подробные сценарии и обработка ошибок: [docs/GEMINI_SEARCH.md](GEMINI_SEARCH.md).

## 4. Загрузка реальных данных Адлера / Сочи

Для уже заполненной БД и запуска поиска скачивать карту повторно не нужно.
Следующая команда заново рассчитывает характеристики; она перезапишет
`data/demo/hotels.json` и `scene.npz`, **но не импортирует их в БД**:

```bash
python -u scripts/build_demo.py --bbox 43.40 39.90 43.46 39.98 --limit 15 --rebuild
```

`--rebuild` нужен, чтобы не использовать старую, в том числе синтетическую сцену.
Ответы OSM сохраняются в `data/demo/raw` и при этом флаге используются повторно.
`--limit 15` ограничивает число рассчитываемых отелей, а не площадь скачиваемых слоёв.
По умолчанию плитка зданий — `--tile 0.02`; список зеркал можно задать через
переменную окружения `OVERPASS_URLS` (URL через запятую).

Загрузка зависит от публичных Overpass-серверов и может занимать долгое время.
`Ctrl+C` сохраняет успешно записанный кэш; текущий запрос или расчёт придётся повторить.
Для продолжения выполните ту же команду с теми же параметрами.

После строки `5/5 готово` проверьте покрытие:

```bash
python -c "import json; r=json.load(open('data/demo/download_report.json')); print('Статус:', r['status'], '| Пропусков:', len(r['missing']))"
```

`complete` — все запрошенные плитки получены. `partial` — сборка завершена с пробелами:
зависимые характеристики получают `value: null`, нулевую уверенность и не участвуют
в рейтинге. Такой результат можно импортировать осознанно или сначала докачать.
`running` означает, что запуск ещё не завершился либо был прерван.
**Успешный код завершения сборщика сам по себе не гарантирует полное покрытие.**

Для замены текущей БД результатом сборки, только после проверки файла и отчёта:

```bash
python scripts/import_hotels.py data/demo/hotels.json --city Сочи
```

Команда удаляет прежнюю БД. Если хотите сохранить её, вместо последней команды
можно импортировать результат в отдельную БД и запустить сайт с ней (macOS / Linux):

```bash
HOTELS_DB=data/real/facts.db python scripts/import_hotels.py data/demo/hotels.json --city Сочи
HOTELS_DB=data/real/facts.db python -m streamlit run app/streamlit_app.py
```

Повторный импорт очистит выбранную `data/real/facts.db`, а стандартную БД не затронет.
Для другого района укажите `--bbox S W N E`; все параметры:
`python scripts/build_demo.py --help`. Для одного отеля:
`python scripts/analyze_point.py --help`.

## 5. Коммуникационный агент

```bash
python scripts/demo_hotelier.py                              # офлайн: готовые ответы и узкий парсер
python scripts/demo_hotelier.py --llm                        # извлечение фактов через Gemini
python scripts/demo_hotelier.py --llm --llm-simulator        # Gemini также играет роль отельера
python scripts/demo_hotelier.py --hotel demo_conflict        # проверка противоречия без сети
```

Реальным людям программа не пишет и не звонит. В интерфейсе ответ вводится
в кабинете отельера; симулятор использует вымышленные карточки. Демо-скрипт не
записывает результаты в БД, а кабинет сайта сохраняет принятые ответы.
Контракты и ограничения: [docs/COMMUNICATION.md](COMMUNICATION.md).

## 6. Тесты, синтетика и метрики

Все автоматические тесты без обращения к Gemini, в отдельной временной копии
со специально подготовленной синтетической БД:

```bash
python scripts/run_tests.py
```

Рабочая БД, кэш, `.env` и реестр характеристик не меняются. Код завершения 1
означает, что подготовка или тесты не прошли. Установленные зависимости нужны;
их установка не является частью этого офлайн-запуска.
Не используйте общий цикл тестов на произвольной реальной БД: некоторые старые
тесты ожидают конкретные синтетические отели `w1..w8`.

Для **намеренной замены** рабочих данных полной синтетикой:

```bash
python scripts/setup_demo.py
python eval/run_eval.py
```

`setup_demo.py` пересоздаёт БД, `hotels.json`, `scene.npz`, удаляет `data/demo/raw`
и отчёт загрузки. **Не запускайте его ради проверки на рабочей папке с нужными картами.**
Метрики записываются в `eval/REPORT.md` и `eval/report.json`. `eval/labels.json`
размечен для синтетики; для реального региона нужен отдельный эталон. Числа метрик
не являются оценкой качества на реальных отелях и могут изменяться после правок.

## Структура и ограничения

| Папка | Назначение |
|---|---|
| `agents/`, `core/` | Gemini-планирование, поиск и объяснение, диалог с отельером |
| `tools/geo/`, `tools/osm*.py`, `tools/pipeline.py` | Карта, рельеф, видимость, шум, пешая сеть и инфраструктура |
| `storage/` | SQLite, источники, сроки актуальности, конфликты и очередь вопросов |
| `app/` | Поиск, сравнение, кабинет, карта, страница «О системе» |
| `features/registry.yaml` | Характеристики; новые критерии также добавляются через кабинет |
| `simulator/`, `schemas/` | Вымышленные отельеры и контракты результатов |
| `scripts/`, `tests/`, `eval/` | Сборка данных, проверки и метрики |

У фактов хранятся источник, уверенность и срок годности. Слова отельера не затирают
георасчёт: резолвер сопоставляет источники и отмечает расхождения. Уверенность —
условная оценка, не доказанная вероятность. Дословная цитата тоже не гарантирует
истинность утверждения или безошибочность интерпретации LLM.

Высоты OSM и рельеф приблизительны, модель шума не откалибрована. Расчёт не знает
конкретный доступный номер, цену или наличие мест. «Вид на море» и «пляж рядом» —
разные критерии. Карта на сайте может загружать подложку через интернет; локальный
сервер не означает полностью автономный режим.

Геоданные не обновляются автоматически: требуется явная пересборка. Синтетика,
реальная БД и кэш — разные наборы файлов; обновление Git не импортирует JSON в SQLite.
Не коммитьте `.env`, `.venv` и случайно добавленный сырой кэш. БД игнорируются Git;
для передачи данных используйте проверенный JSON и инструкцию импорта.
